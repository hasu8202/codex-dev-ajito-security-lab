# アジト防衛演習室 — 設計

## 目的

公開済みの「情報屋アジト」と同じ地下情報屋のUIと、入会・掲示板・追記・密談・管理室という利用の流れを使い、大学の初級〜中級の学生が認可や入力処理を安全に学べるローカル限定の演習環境を作る。

## 目標

- Next.js、React、Tailwind、Drizzle/libSQLを使い、元アプリの画面構成・デザイン部品・テスト用データを再利用する。
- すべての実行経路をローカルに限定し、既定の開発・起動コマンドは `127.0.0.1` のみへバインドする。
- 本番公開、Cloudflare、D1、リモートDB、実アプリのCookie名、実アプリのデータ、秘密情報を一切含めない。
- 初期化コマンドで教材DBを消去・再作成・シードできる。
- 各演習は、対象画面、学習目標、成功判定、修正後に確認するテストを説明書に載せる。

## 非目標

- 本番運用やインターネット公開、実ユーザーの登録、外部サービス連携、実サービスへの攻撃を行わない。
- 実アプリへ脆弱な変更を戻したり、実アプリのDB・環境変数・認証情報を読んだり複製したりしない。
- 一般の第三者を標的にできる攻撃手順や自動化ツールは作らない。

## 方式の比較

1. 実アプリへ教材用の切替を追加する方式: UIの再現性は高いが、公開済みアプリと混線するため不採用。
2. 画面だけを模した小型デモを新規実装する方式: 隔離は容易だが、実アプリの挙動を学ぶ教材になりにくいため不採用。
3. 同じ構成を別リポジトリ・別DB・別Cookie名で複製し、ローカル専用の演習機能を加える方式: 画面と仕組みを維持しながら実サービスと分離できるため採用。

## 構成

元アプリのNext.js App Router、Drizzle/libSQL、Server Actions、デザイン部品を複製する。公開・Cloudflare用の設定と依存関係は外す。アプリの起動時にはローカル実行を検査し、プロセスが外部公開向けに起動された場合は失敗させる。DBは `data/ajito-security-lab.db`、Cookieは専用名とする。

教材として、認可・情報公開・入力の扱いに関する複数の課題を、すべて架空アカウントとローカルDBだけで再現できるようにする。課題実装は教材レイヤーに閉じ、問題ごとに無効化・修正の比較ができる説明とテストを用意する。

## 受入条件

- `npm run dev` と `npm start` が localhost 専用の専用ポートで起動する。
- `npm run db:reset` が教材DBをシード済みの初期状態へ戻す。
- `npm test`、型検査、lint、production buildを一括検証で通す。
- READMEに隔離上の注意、起動・初期化方法、演習ルール、テスト用アカウントだけを記載する。
- Git履歴に本アプリの `.env`、DB、トークン、リモートURLが含まれない。
